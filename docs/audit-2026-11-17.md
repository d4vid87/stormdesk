# MyStormDesk implementation audit — November 17, 2026

## Scope and status

Reviewed the working tree based on `8e86b3c` (version 4.10.3), including the existing, uncommitted Observatory / Sky Theater / Weather Changes preview. Inventory covered 401 tracked files, the full application, Lite, Rust services, packaging, CI, and deployment configuration. Generated build directories were excluded. Existing design work was preserved. The audit was completed locally before release preparation; these changes are included in the 4.11.0 release. No production station configuration was changed by the audit.

This is an implementation audit with reproduced defects and regression tests, not a claim that every possible defect or hardware-specific performance problem has been eliminated.

## Architecture and critical paths

| Area | Implementation and execution path |
| --- | --- |
| Full browser app | Plain ES modules, HTML and CSS; no React/Vue renderer or npm runtime dependency graph. `boot.js` wires feature modules; `app.js` owns settings, navigation, notifications and the named refresh scheduler. `wd:*` events distribute observations, forecasts, settings and navigation changes. |
| Main dashboard | `desk.js` obtains data; `pro.js`, `observatory.js`, `forecast-desk.js` and `balanced-desk.js` update persistent DOM. `motion.js` coordinates number animation; CSS/SVG animate weather artwork. |
| Weather pipeline | `api.js`, `weather-providers.js` and weather context modules normalize station/WeatherFlow/Open-Meteo/NWS and specialist feeds. Forecast/location identity and unit conversion must remain consistent across async responses. Existing browser memo/ETag caches are bounded and requests are deduplicated. |
| Radar | The full radar is a cross-origin `app.hookecho.io` iframe. StormDesk owns lazy loading, lifecycle, camera persistence and still-image fallback. HookEcho owns radar decoding, tile caches, WebGL resources and frame pacing; its implementation is not in this repository. |
| History | Lazy-loaded History modules draw canvas charts with keyboard controls and accessible sample tables. SQLite supplies station history; Lite also keeps bounded browser samples. Large-series preparation and pointer redraws are sensitive paths. |
| Lite | Separate, smaller ES-module UI under `site/lite/`, sharing the weather API. It has its own location, alert, history-cache and optional radar lifecycle. |
| Desktop/mobile | Rust 2021 + Tauri 2. Desktop embeds the site with `include_dir`; Android uses the Tauri/Kotlin wrapper. `gui` is optional: the headless binary excludes desktop WebKit/GTK. |
| Local server | `tiny_http` with a local transport patch, four normal workers, two upload workers and two queued uploads; separate bounded SSE and download paths. Owner/paired-editor checks guard settings and maintenance. Public weather endpoints remain intentionally available to reachable viewers. |
| Station collection | UDP 50222 plus push ingestion; WeatherLink Live roughly 10 s, Ambient 60 s, La Crosse 120 s. Data are normalized and written to the selected station archive. |
| Background integrations | MQTT publisher about 10 s with bounded outbox, CWOP 10 min, upload relays 60 s, alerts 60 s, environmental collection 120 s. These have their own worker lifecycles. |
| Storage | SQLite WAL, `synchronous=NORMAL`, busy timeout, timestamp primary key, channel composite key and exclusion index. Daily summaries have persistent caches and invalidation triggers. Raw history windows are bounded; backfill uses four-day chunks and checks station generation. Retention prunes in seven-day chunks. |
| Delivery | `site/` is the Cloudflare Pages app at app.mystormdesk.com; `marketing/` is the separate mystormdesk.com site. GitHub Actions creates signed updater artifacts and platform installers; Docker builds the headless binary. Flatpak vendors the locked Rust crates. |

The important costs are repeated DOM/Intl work, chart preprocessing, external radar ownership, concurrent blocking upstream requests, archive scans, and long-lived stream/cache bookkeeping—not framework component reconciliation.

| Abandoned pending radar observation | One retained IntersectionObserver | Zero, including a 100-navigation-cycle regression |
| Full/Lite live radar document while page hidden | One iframe document remains loaded | Zero; only the selected radar resumes on return |

## Implemented fixes

### Security and credential boundaries

- Reject unrelated/opaque browser Origins before granting implicit local-owner access. Independently require a loopback Host for loopback owner access, closing the matching hostile Host/Origin DNS-rebinding path. Preserve same-origin local use, native Tauri and explicitly paired bearer clients.
- Normalize Fetch inputs with `Request` before attaching editor credentials. URL objects and Requests from another constructor no longer cause credentials to be attached to an external destination. Existing headers and request bodies are preserved.
- Render external warning/diagnostic text safely; use text nodes for History errors and NWS period names. Provider strings cannot become ticker or tooltip markup.
- Restrict the service worker to public shell destinations; exclude pairing/API/authenticated requests, respect private/no-store responses, use only its own cache, and retire the old cache namespace. Cache storage/quota failures no longer break successful online loads or leave rejected background writes.
- Return an opaque hash instead of raw station identity in public archive coverage metadata. The raw identity could contain an ingest credential or account identifier.
- Fail pairing-code creation with HTTP 503 if secure randomness fails instead of emitting a predictable fallback code.
- Read HA URL and token from the same configuration snapshot; protect against mixing a new credential with an old endpoint during changes.
- Create Unix configuration, backup and restore-staging files with owner-only permissions before writing. Tighten the existing configuration on startup. Windows retains OS ACL behavior; older exported files are not mass-modified.

### Rendering, memory and background work

- Initialize each number tween's start timestamp on its first animation frame. Updates after startup now animate over their intended duration instead of jumping immediately.
- Bound dashboard timing entries and reuse clock formatters; skip unchanged date/time-zone DOM writes.
- Reuse chart preparation/accessibility groups on pointer redraws and compute extrema without large spread argument lists. New data still invalidates the preparation; full samples and original-point tooltips remain available.
- Cancel pending radar observers and idle callbacks when leaving the view. Unload cross-origin radar documents when hidden; restore only the active view.
- Deduplicate backend forecast, HA and drought cache fills. Other workers return an explicit unavailable/in-progress result promptly rather than waiting behind slow upstream I/O. Failed upstream results have a short retry TTL.
- Remove disconnected SSE subscribers without waiting for a station broadcast.
- Bound UDP packet storage to eight supported packet types, bound pairing-attempt state, and cap simultaneous large CSV/backup responses at four. Excess downloads return 503; permits are released on completion/error/disconnect.
- Give CWOP TCP connection attempts a shared ten-second deadline. OS hostname resolution is still outside that deadline.
- Canonicalize Lite's API import so its lazy History feature shares the same module and caches.

### Weather correctness and reliability

- Key native forecast/HA/drought caches to the relevant configuration and recheck identity after upstream I/O. Old-location forecasts and old HA entities are not served as current data.
- Bind browser station-observation overlays to station/profile/device/location identity, and reject implausibly future-dated observations.
- Respect holes in Polygon/MultiPolygon severe-weather areas; an excluded interior no longer receives the surrounding risk classification.
- Convert NWS temperatures into the selected units before comparing them with station forecasts.
- Guard Lite warning results and failures by location/request generation. Old requests cannot replace a newer location's warning banner or dialog.
- Isolate Lite observation/history caches by source/device/profile. Legacy entries remain stored, but are not silently attributed to a newly selected station.
- Parse quiet-hour settings without slicing arbitrary UTF-8 byte offsets. Malformed text no longer panics and kills the alert worker.
- Use saturating arithmetic for retention cutoffs. A malformed enormous retention setting cannot overflow into a panic or an unintended deletion cutoff.

### Dependencies, builds and maintenance

- Replace yanked `async-executor 1.14.0` with compatible `1.14.1`.
- Regenerate the Flatpak offline sources/checksums from Cargo.lock and add a consistency check to CI.
- Use locked dependencies for the Docker build and Rust CI checks; explicitly limit CI's repository permission to read access.
- Add regression suites to CI, including the existing uncommitted Sky Theater and Weather Changes checks.
- Correct SECURITY.md, README and the technical reference: `/public` is a redirect, not a security boundary. Document paired editors, legacy access and proxy behavior.
- Advisory checking passes. Bundled SQLite already uses `libsqlite3-sys 0.39.1`, above the patched boundary in [RustSec RUSTSEC-2026-0459](https://rustsec.org/advisories/RUSTSEC-2026-0459.html). Existing specific maintenance exceptions remain; no broad ignore was introduced.

## Compatibility and remaining limits

- A custom reverse proxy no longer becomes an editor merely because its backend connection is loopback. Preserve the public Host and use paired credentials for editing. Explicit legacy LAN access remains a compatibility option and continues to trust the LAN; disable it after pairing trusted screens.
- Lite's old browser cache is preserved but not reused without sufficient identity information. Station archives and settings are not deleted or migrated away.
- Release preparation aligns the native and Flatpak manifests with v4.11.0; release artifacts must be built from that tag.
- No Windows/macOS/Android installer build, signing, update installation, physical low-powered-device run, or multi-hour native WebKit/GPU soak was performed. The 15 browser fixture runs do not replace those release checks.
- HookEcho frame pacing, internal tile eviction and GPU allocations need a separate audit of HookEcho. StormDesk lifecycle/resource-count checks do not establish a specific GPU or FPS gain.
- Tauri's CSP is still null. A restrictive policy needs testing against native IPC, embedded radar, user-configured stations/integrations and the existing inline shell. Tauri documents these policy requirements in its [CSP guide](https://v2.tauri.app/security/csp/).
- Cold multi-year aggregate latency remains measurable; the current warm cache is effective. Investigate production-profile cold-query plans before changing archive semantics or indexes.
- The slow-upload worker exhaustion is fixed in the follow-up below. Connection-flood limits, reverse-proxy rate limiting and production internet load testing remain outside this change; bounded upload workers are not a general DDoS guarantee.
- OS DNS resolution is still outside the CWOP connection deadline. Older archive files/exported backups retain their existing permissions; only the current configuration and newly written credential-bearing files are tightened.

Publication status is recorded in the GitHub release; the measurements here describe the local pre-release validation.

## Slow-upload follow-up — November 17

The same isolated raw-socket test failed against a saved pre-fix binary: six incomplete fixed-length/chunked/Expect uploads blocked four normal endpoints beyond 750 ms. With the fix, those endpoints completed in 5.6 ms while the uploads remained stalled. Idle bodies expired after 10.4 seconds and a client sending a byte every 250 ms still expired at the 30-second absolute deadline. These are local debug-build measurements, not internet latency guarantees.

- Two fixed upload workers and two queue slots isolate every framed body (including GET, rejected and upgrade requests) from the four normal HTTP workers. Queue overflow closes the connection without draining it or waiting to write a response.
- A narrowly patched, licensed copy of tiny_http supplies socket cancellation, ten-second idle read/write limits and per-request deadlines. It avoids eager small-body reads, bounds discard buffers at 8 KiB, and reports truncated fixed-length bodies as errors.
- Every mutation body must be complete and within its route limit. The archive-replacement confirmation is read before taking the configuration lock. Authorized POST backup inspection retains its 8 GiB cap and has a 30-minute total upload allowance; other bodies have 30 seconds.
- Responses serialize on each HTTP/1.1 connection before another request is dispatched. Pipelined requests behind SSE therefore cannot consume the normal workers while waiting for response order; keep-alive and independent connections still work.
- The isolated HTTP regression covers overload, ignored/unauthorized bodies, partial JSON without persistence, valid JSON/chunked/ingest/100-continue/keep-alive, archive lock isolation, a real backup inspection, failed restore cleanup, timeout recovery and SSE delivery. CI also runs the vendored transport tests and checks Flatpak dependencies.

Reproduce with:

```sh
cargo test --locked --manifest-path src-tauri/Cargo.toml -p tiny_http
node scripts/check-upload-isolation.mjs
```

Final follow-up validation passed: 108 GUI-feature Rust tests (two ignored), 105 headless Rust tests (one ignored), 31 transport unit/network/documentation tests, both isolated HTTP suites, and the 551-package Flatpak lockfile consistency check. GUI/headless suites overlap and must not be added as distinct tests. Windows, macOS, native TLS and installer builds were not exercised in this follow-up.

The follow-up was validated before release preparation. It is included in v4.11.0; no live station configuration was changed during testing.
